# Website to AI Cold Email Opener

Generate personalized, website-grounded **three-line openers** for founder outreach. Paste a company URL; the app fetches the page, extracts meaningful text, and asks Google Gemini for exactly three lines:

1. what the company does,
2. one specific observation taken from its website,
3. a natural conversation starter for the founder.

It never writes a full email — only the opener — and it refuses to guess when a site cannot be read.

## 1. Features

- URL normalization (`company.com` → `https://company.com/`) and SSRF-safe fetching
- Clean content extraction (title, meta description, headings, main text; no scripts, nav, footer or cookie banners)
- Gemini generation with a prompt-injection-hardened prompt and strict output validation (one controlled regeneration)
- Result cards, extracted-content summary, **Copy Opener**, **Generate Again**, **Clear**
- **Demo mode** that works without an API key (clearly labelled, fictional samples)
- In-memory caching of extracted sites and generated openers, retry with backoff for transient errors
- Sidebar **cost estimator**
- 130+ automated tests with mocked HTTP and mocked AI (no API key needed)

## 2. Tech stack

Python 3.11+ · Streamlit · Requests · BeautifulSoup4 · Trafilatura · `google-genai` (official Google Gen AI SDK) · python-dotenv · pytest

## 5. API key setup

1. Create a free key in [Google AI Studio](https://aistudio.google.com/apikey).
2. Copy `.env.example` to `.env` and edit it:

```env
GEMINI_API_KEY=your_api_key_here
GEMINI_MODEL=gemini-3.1-flash-lite
```

`GEMINI_MODEL` is configurable. Google renames and retires models regularly, so **check the current model list and free tier in AI Studio** and change this value if you get a "model not found" error. Never commit `.env` (it is in `.gitignore`).

Optional settings (see `.env.example`): `MAX_CONTENT_CHARS`, `REQUEST_TIMEOUT_SECONDS`, `CACHE_TTL_SECONDS`, `MAX_RETRIES`, `PRICE_INPUT_PER_1M_USD`, `PRICE_OUTPUT_PER_1M_USD`.

## 7. Using the app

1. Enter a company website URL (with or without `https://`).
2. Click **Generate Opener**. A status panel shows each step (validate, fetch, extract, generate, validate).
3. Review the company description, the extracted-content summary and the three-line opener.
4. **Copy Opener** copies the three lines. **Generate Again** requests a fresh variation (the extracted page is reused from cache). **Clear** resets the page.

Always review an opener before sending it.

## 8. Demo mode

If no API key is configured, the app starts in **Demo mode** automatically (you can also toggle it in the sidebar). It offers three *fictional* sample companies and pre-written openers, makes no network or AI calls, and labels every result:

> DEMO OUTPUT — Not generated by a live AI model.

## 9. How website extraction works

1. The URL is normalized and validated (scheme, host, port, no credentials).
2. DNS is resolved and **every** resolved address must be public. Redirects are followed manually (max 5) and each hop is validated again.
3. The page is streamed with a timeout, a descriptive User-Agent, an HTML-only content-type check and a 2 MB size cap.
4. Trafilatura extracts the main text; BeautifulSoup supplies the title, meta description, headings and a fallback text extractor. Scripts, styles, nav, footer, forms, cookie/consent/popup elements and duplicate lines are dropped.
5. Text is truncated (default 6,000 characters) to keep prompts small.
6. If almost nothing is extracted, the app shows a specific error (JavaScript-rendered site, blocked by the site, empty page) instead of guessing.

## 10. How AI generation works

- The system prompt defines the task, the three-line structure, style rules (no clichés, no invented facts, no claims of having used the product) and **security rules**.
- Website content is wrapped in `<website_data>` delimiters and sanitized (control characters and delimiter look-alike tags removed) so the page cannot close the block.
- The output is cleaned (markdown, numbering, labels removed) and validated: exactly 3 non-empty lines, length limits, no greeting/subject/signature, no banned clichés.
- Invalid output triggers **one** controlled regeneration; if that also fails the user sees an error, never invalid output.
- Transient errors (rate limit, 5xx, network) are retried with exponential backoff; invalid keys, missing models and daily quota exhaustion are **not** retried.

## 11. Security considerations

- **SSRF:** localhost, `.local/.internal` names, private/loopback/link-local/reserved IPv4 and IPv6 (including IPv4-mapped) are rejected; only ports 80/443; no URL credentials; redirects re-validated. *Residual risk:* DNS can change between the check and the connection (DNS rebinding). For a hardened production deployment, run the fetcher in an egress-restricted network or pin the resolved IP.
- **Prompt injection:** website text is treated as data; the prompt explicitly forbids following instructions inside it; the API key and environment are never put in prompts; output is validated so it cannot be a free-form answer.
- **Secrets:** read from environment/Streamlit secrets, never hardcoded, never logged (errors are redacted and users only see friendly messages).
- All text shown in the UI is HTML-escaped.

## 12. Limitations

- JavaScript-rendered sites (React/Next SPAs with no server-rendered text) cannot be read; the app tells you so.
- Sites that block bots or show challenge pages are reported as blocked.
- Only the submitted page is read (use a specific page such as `/about` for richer results).
- Caches are in-memory and reset when the server restarts.
- Output quality depends on the page text; always review before sending.
- I could not run live Gemini calls or fetch real websites in the build environment (no API key, restricted network), so live behaviour is verified through mocks and the demo flow only.

## 14. Cost considerations

**Estimated tokens per request** (characters ÷ ~4 per token):

| Part | Tokens |
|---|---|
| System prompt | ≈ 600 |
| Website data (≤ 6,000 chars + title/meta/headings) | ≈ 1,500–1,700 |
| **Input total** | **≈ 2,300** |
| Output (three lines) | ≈ 100–150 (more if the chosen model "thinks"; thinking tokens are billed as output) |

**Formula:** `cost = (input_tokens × input_price + output_tokens × output_price) / 1,000,000`

**Example at 1,000 requests/day.** Assumptions: 2,300 input and 150 output tokens per request, and the prices below, which appeared on Google's Gemini API pricing page for `gemini-3.1-flash-lite-preview` when this project was built (**$0.25 input / $1.50 output per 1M tokens**, paid tier, standard). Prices and model names change; **verify on the official pricing page (https://ai.google.dev/gemini-api/docs/pricing) before relying on this.**

- Per request: 2,300 × 0.25 / 1M + 150 × 1.50 / 1M ≈ **$0.0008**
- Per day (1,000 requests): ≈ **$0.80**; per 30 days: ≈ **$24**
- Add roughly 5–15% for regenerations and retries. Caching removes repeat calls for the same URL.

The sidebar **Cost estimator** recalculates this with your own numbers.

**Free tier:** Google offers a free tier for some Gemini models, with lower rate limits (requests/minute, tokens/minute, requests/day), and free-tier content may be used to improve Google's products. Availability, quotas and limits change and differ per model; check Google AI Studio for your project's current limits. 1,000 requests/day may exceed free-tier quotas, so plan for the paid tier at that volume. HTTP 429 errors mean you hit a rate limit or quota.

## 15. Deploy on Streamlit Community Cloud

1. Push this folder to a GitHub repository (make sure `.env` is **not** committed — it is git-ignored).
2. Go to https://share.streamlit.io, click **Create app**, pick the repo and branch, and set the main file to `app.py`.
3. Under **Advanced settings → Secrets**, paste:

   ```toml
   GEMINI_API_KEY = "your_api_key_here"
   GEMINI_MODEL = "gemini-3.1-flash-lite"
   ```

4. Deploy. Use Python 3.11 or newer in the advanced settings if prompted. Without a key the deployed app still works in Demo mode.

Do not put the key in the repository or in `.streamlit/config.toml`.
